## 1. 项目目标

一个可不断迭代的智能电吉他综合效果器平台：

- **双端兼容**：PC（独立应用 + VST3/AU 插件）与嵌入式设备（Linux SBC / MCU）共享同一引擎，修改一端另一端同步更新
- **综合效果器功能**：多个预设；每个预设一条音色链，≥8 槽位（架构可扩展，槽位数对外不作营销话术）；槽位可放单块 / 箱头 / 箱体模块
- **低延迟**：5ms 为目标、8ms 为验收底线（端到端含 I/O）
- **三种音色技术**：
  - **NAM**（黑盒建模）：官方 NAM Core，加载 .nam，支持 A1 / A2（slimmable，Full/Lite 档）模型文件；微调能力受限（gain/三段EQ/output）
  - **IR**（箱体/空间模拟）：WAV 卷积
  - **DSP**（白盒/灰盒建模）：电路仿真算法，全参数可调，弥补 NAM/IR 微调能力的不足

### 产品定义（评审补充）

- **用户**：追求音色自由的吉他手（含练习、录 demo、低成本演出场景）
- **替代品参照**：Tonex（捕获+低价硬件）、Neural DSP / Amplitube（插件+模型目录）、Katana（价格与可靠性）、免费 NAM 宿主（官方插件、ToneLib）
- **差异化押注**（三选一，当前定调"开放格式 + 社区生态 + 价格"）：不锁死用户、可加载社区海量 .nam/IR、SBC 硬件成本为商业踏板的 1/5–1/10
- **护城河不在"做 NAM 播放器"**（无壁垒），而在内容（预设/IR 包）、社区（分享生态）、硬件或价格——预设分享与生态列为后续迭代方向

## 3. 核心架构原则

1. **引擎与一切隔离**：全部音频处理逻辑在纯 C++17 核心库中，**音频路径零第三方运行时依赖**；预设加载/JSON 序列化路径允许 header-only 豁免（nlohmann/json，v0.7 #94）。桌面端与嵌入式都是薄壳。嵌入式专用设计（HAL、能力分级、A2 档位选择）在桌面 v1 发布前冻结，不反向污染桌面架构。
2. **音频线程实时安全**：回调内禁止堆分配/锁/I/O/异常；UI→引擎参数走无锁 SPSC 队列 + 参数平滑。
   - 平滑策略需明确定义（线性/指数、最大平滑时间 ≤10ms），与 bypass/交叉淡化协调，避免"旁路闪音"
   - **图交换协议**：所有音频图变更走 "request → 后台加载 → 双缓冲原子交换"，UI 只改"待切换图"指针，音频线程在 block 边界交换
   - **过载策略**：处理超预算时输出静音 + 标志位 + 统计，不重复上一 block
3. **引擎是参数权威**：UI 显示只读镜像，经队列订阅引擎广播；切换预设即终止当前自动化。参数系统（自动化、平滑、宿主自动化总线）是 core 能力，不是桌面壳的职责。
4. **单一预设格式**：JSON 双端共享，带 schema 版本 + **迁移链**（逐版本迁移函数）；"低版本设备打开高版本预设"策略明确（拒绝但保留原文件）。
5. **性能分级**：平台能力声明 + 后台线程运行时实测校准（用 cycle counter，不用系统时间）；预算红线 = 平台实测单回调预算的 80%；降级顺序用户可配置（默认按模块耗时降序）；剩余性能可显示。
6. **持久化可靠性**（v0.7 #96/#97）：所有持久化写入走原子协议 temp → fsync(file) → rename → fsync(dir) → 读回校验（ext4 上 rename 不保证断电原子性）；现场状态记忆变更后 debounce 保存，断电窗口只 mute。
7. **参数写优先级**（v0.7 #95）：场景 recall > 控制源 > UI 写入；绑定期 UI 写入 = 深度 1 排队；控制源回落（hang-time 100-300ms）走参数平滑路径。

## 5. 音色链引擎

- Preset → Chain（≥8 槽位，可扩展）→ 槽位 = `{ 类别: pedal|amp|cab, 实现: nam|ir|dsp, 模块ID, 参数, bypass, mix }`
- 旁路带交叉淡化防爆音；**淡化长度按模块类型定义**（IR 类 5ms、DSP 类 1ms，避免相位梳状声）；每模块干湿比（mix）
- **模块注册表**：以 `模块ID` 为全局唯一键（类别是模块的属性，可查询可校验），工厂 `create(module_id, context)`；预设加载时对每槽**显式合法性校验并报错**，不做静默失败；构建期做重复 ID 检测测试
- **模块生命周期接口**：`prepare(sample_rate, block_size)`（幂等可重入，处理 block size 变化与采样率切换，切换时全链 reset）、`process()`、`reset()`、`set_sample_rate()`、`set_max_block()`——资源所有权由模块自管
- **声道处理模型**：引擎内部立体声（模块接口 stereo in/out），每模块声明自己的声道模式（mono in/mono out、mono in/stereo out、stereo in/stereo out），输入自动适配、链自动传递；吉他单块类 = mono in/mono out，立体声效果（合唱/延迟/混响）= mono in/stereo out，IR 箱体 = mono in/stereo out（双 IR/立体声 IR）
- 采样级串行处理，**默认 48kHz，44.1k 可选**（嵌入式 codec 48k 域原生；44.1k 档嵌入式需重采样）；**96k 下 NAM 需内部重采样或 48k 域处理**（A2 模型训练采样率固定，**M4 交付——M4 开头 spike 定重采样 vs 48k 域**，v0.7 #105）
- **重排链期间**切干音直通 + 释放时渐入，纳入防爆音回归测试
- **MIDI 事件抽象**（core 能力）：引擎层定义 MIDI 事件输入（CC/PC），参数系统可响应 MIDI 学习映射；桌面壳实现 USB-MIDI 设备驱动

### 控制源抽象（v0.5 定稿，M5 前落地）

- **ControlSource 统一接口**：归一化 0..1 输入源（表情踏板/MIDI CC/Web UI/桌面 UI/脚踩开关），映射链（曲线/反转/范围）+ Binding 三元组（源→参数）
- **多源仲裁（绑定语义）**：写优先级 = **场景 recall > 控制源 > UI 写入**；参数被某控制源绑定时（踏板/CC），UI 写入进入深度 1 排队；源释放检测（hang-time 100-300ms）后**经参数平滑**回落到 UI 值（未平滑的回落本身即 zipper）。被绑定参数在 UI 显示来源徽标（"踏板控制中"）+ 悬停提示。演出中 Web UI 与实体控制并发由此裁决，杜绝 block 粒度跳变（zipper）
- **每源每参数平滑配置**：CC ~10-20ms、踏板 ~1-3ms、whammy 专用低延迟通道（绕过统一 ≤10ms 平滑）；CC 用 14-bit（MSB/LSB）防 7-bit 量化感
- **表情踏板硬件边界**：10k-100k 电位器兼容偏置网络、ADC 分辨率/扫描率、wiper 噪声滤波、min/max 校准、极性

### 场景引擎实现（v0.5 定稿）

- **8 场景缓冲放引擎侧**（嵌入式脚踩切换无 UI 线程，只能向引擎发 recall 命令）
- **一次性场景应用消息**：预构建定长 POD 参数数组（实时安全无分配），音频线程在 block 边界整体原子切换；**模块声明"立即生效"（bypass/master）或"平滑生效"（滤波器类参数）**；场景交叉淡化走独立固定 ≤10ms ramp，不受源平滑配置影响
- **场景 recall × 图交换**（v0.7 #100）：预设切换/图交换进行中收到的场景 recall = 过渡完成后应用（不静默丢弃）；同 block 边界顺序 = 先 swap 后场景（场景参数按模块 ID 寻址，swap 后 ID 集可能变化）
- **场景不改链拓扑**（只改开关+参数），因此切换走即时参数应用（≤10ms），**不走干音直通（G12）**
- **数据模型**：live buffer → 显式"存储到场景" → 场景槽；未存修改遇外部触发（脚踩/PC）→ 丢弃 + 警示（桌面确认框/嵌入式图标），不静默覆盖
- **undo/redo 语义**：场景指针切换可 undo；切预设清空 undo 栈；A/B 不入 undo 栈；undo 是**壳侧 UI 概念**（桌面壳与 Web 壳均实现，v0.7 #76，经 SPSC 命令交互，引擎不背 undo）；LCD 不提供 undo
- **场景持久化**：scenes 字段进预设 schema（v1 定死，M5 前）；场景可命名（≤8 字符，LCD 友好）；"现场状态记忆"= **变更后 debounce 周期保存（2-5s）** 的现场状态，独立于 8 场景槽，写入走原子协议（§3 原则 6），开机 CRC 校验失败回退最后完好状态

### 录音总线（UAC2 用，M7 前定稿）

- dry tap：输入增益后、链前；wet tap：master 后、全局 EQ 前（全局 EQ 为房间调音不进录音）
- 各自电平控制；UAC2 捕获声道配置（wet 2ch + dry 2ch = 4ch capture）

## 6. 三大音色技术

| 技术 | 定位 | 实现 | 微调能力 |
|---|---|---|---|
| NAM | 黑盒建模 | 官方 NAM Core（FetchContent + 固定 commit，独立静态库），A1/A2（Full/Lite 档）模型文件均可加载 | 受限（gain/三段EQ/output） |
| IR | 箱体/空间模拟 | 分区卷积（UPOLS + 非均匀分区），WAV 加载 + 一次性高质量重采样（最小相位）并缓存 | IR 增益、低切/高切、位置参数 |
| DSP | 白盒/灰盒建模（**名单块数字复刻路线**，v0.8 #110 用户拍板） | 每个类别以著名单块为参考复刻其特征：过载=TS808/Klon/OCD/RAT 风格（**电路级 WDF**，非线性削波是音色关键）、压缩=Dyna Comp 风格（电路级 OTA）、合唱=CE-2 风格（BBD 仿真）、相位=Phase 90、镶边=BF-2、哇音=Crybaby、延迟=DM-2 模拟 + Echoplex 磁带风格、混响=弹簧物理模型 + 经典算法（Hall/Plate）、EQ=GE-7 风格、门限=NS-2 风格、**音高家族**（单音假设，算法路线）；命名全部改名规避商标；WDF 从 P2 提前入 M2 | 全参数可调 |

音高家族实现要点（v0.5 定稿）：

- **单音假设**（v1 明确声明，吉他独奏场景）：音高检测（YIN/McLeod）+ WSOLA/相位声码器移调核心；单音八度（整流/倍频整形，近零延迟）
- **和声器 = 移调核心 + N 路并联 + mix/pan**（核心做好后为增量，不独立膨胀）
- **复音八度/复音和声后置**（谐波锁定，数月级）
- **分模块延迟预算表**：音高模块算法延迟 10-30ms 天然存在，**豁免 5ms 全局断言**，听感延迟单独标注；whammy 走专用低延迟控制通道

关键质量约束：

- **IR 重采样**：与参考实现（直接时域卷积，double 精度）最大误差 < -100dB；超长 IR 按平台档位 `max_ir_seconds` 上限拒绝（不静默截断——截断会改变音色）
- **WDF 稳定性**：每个电路建模模块必须有**参数空间扫描测试**（参数网格 + 输出有限且能量有界），CI 强制；48k/96k 双率跑
- **NAM 多实例**：同预设 2-3 个 NAM 实例并发压力测试（内存/CPU/线程安全）

## 7. 预设格式（JSON）

```json
{
  "schema": 1,
  "name": "Clean Edge",
  "chain": [
    { "slot": 0, "category": "pedal", "impl": "dsp", "module": "compressor", "params": {...}, "bypass": false, "mix": 1.0 },
    { "slot": 1, "category": "pedal", "impl": "nam",  "module": "ts9", "file": "ts9.nam", "params": {...} },
    { "slot": 2, "category": "amp",   "impl": "nam",  "module": "jcm800", "file": "jcm800.nam", "params": {...} },
    { "slot": 3, "category": "cab",   "impl": "ir",   "module": "cab_v30", "file": "v30_57.wav", "params": {...} },
    { "slot": 4, "category": "pedal", "impl": "ir",   "module": "reverb_hall", "file": "hall.wav", "params": {...} }
  ]
}
```

格式约束：

- **参数用物理单位**（dB/Hz/%），min/max/单位/taper 由模块注册表提供，UI 从注册表读取渲染；自动化数据在 JSON 中显式存储
- **元数据**：名称 + 收藏星标（无标签/作者/时间字段，避免 schema 膨胀）
- **required 字段约束**（slot/category/impl/module 必填）；逐槽校验 + 默认参数填充 + 完整加载报告
- **两种加载模式**：容错加载（UI 模式，缺失槽位旁路并标注）与严格加载（CI 模式，任何异常即失败）
- **文件路径三件套**：预设自包含优先（资产复制进预设目录，存相对路径）+ 绝对路径回退 + 断链 UI 修复流程（槽位标红可点击"定位/替换文件"）
- **统一目录结构**：桌面 `~/.namfx/`、嵌入式 `/opt/namfx/`，含 `presets/`（预设 JSON）、`models/`（.nam）、`irs/`（.wav IR）、`backups/`（自动备份）；预设自包含时资产复制进 `presets/<预设名>/` 子目录；导出/导入预设即复制整个目录，双端一致
- **备份策略（v0.7 修订）**：预设每次保存时自动写 `backups/`（保留最近 5 版）；恢复出厂/固件升级前全量备份；**写入原子协议 = temp → fsync(file) → rename → fsync(dir) → 读回校验**（ext4 上 rename 不保证断电原子性）；**用户可见恢复流程**（设置页：备份列表 → 预览 → 恢复 → 结果报告，备份不可恢复等于没有备份）
- **导出/导入（v0.7 #67 恢复二轮承诺）**：预设导出/导入 = 目录打包 + 断链修复 + 双端一致，写入 M5a 验收；**USB 存储模式（MSC）**支持导出/导入整个 `.namfx` 目录（UAC2 是音频类，不承载文件导出）；导入向导：重名冲突 / 高版本 schema 拒绝（原文件保留位置可见）/ 缺资产逐项报告
- **JSON 序列化实现**：core/preset 使用 nlohmann/json（header-only，MIT，加载路径非回调内）；schema 迁移链逐版本函数不变

## 8. 性能分级系统

- `PlatformCapabilities`：Full / Limited / Minimal 三档，每档声明允许加载的 NAM 模型架构与 **A2 档位（Full=8ch / Lite=3ch）**、最大 IR 长度、最大混响尺寸
- 运行时实测：**后台线程**基准测试各模块推理耗时（不抢音频线程预算），cycle counter 计时，结果作为档位输入之一
- **加载时成本判定**：演出中加载新模型前用参数量预估 + 当前负载判定是否超预算（拒绝/降级建议），而非加载后由仪表提示
- **A2 bake-off 前置 M4**（v0.5 裁决）：用 RK3308/RK3328 ev board 实测 A2 Full/Lite 档推理实时性（官方无量化路径，.nam 权重固定 float32），再定主力档芯片——不前置承诺"RK3308 主选 + 全系支持"
- 性能仪表：常驻底部细条 + 悬停展开明细；颜色语义统一为**剩余性能**（>50% 绿 / 20-50% 黄 / <20% 红，v0.7 #84）；过载时非打断式警示并指出被降级模块；限定刷新频率避免干扰演奏
- 降级策略：低档平台 **slimmable A2 文件经用户显式确认后以 Lite 档加载**（用户裁决：不做自动降档，避免音色在不知情时变化）；非 slimmable 文件才拒绝并提示换 A1；降级后保持显式标记（槽位内显示"以 A2-Lite 档加载"标签），绝不静默

## 9. 延迟预算（5ms 目标 / 8ms 底线）

| 平台 | 缓冲方案 | 预计端到端 | 契约 |
|---|---|---|---|
| 桌面 (WASAPI/ASIO/CoreAudio) | 48kHz / **64 样本** | ~3-4ms | **5ms 目标档** |
| 桌面 | 48kHz / 128 样本 | ~6-7ms（2×2.67ms 缓冲 + I/O 开销） | 8ms 底线内 |
| 嵌入式 Linux | 48kHz / 64 样本 + RT 内核调优 | ~3.5-5ms（以实测为准） | 5ms 目标档 |
| 嵌入式 Linux | 48kHz / 128 样本 | ~6-8ms | 8ms 底线档（默认） |
| MCU | 48kHz / 64 样本 + DMA 双缓冲 | ~3ms（研究性） | 研究性 |

> v0.7 #98 修订：128 样本 = 2.67ms/周期，双缓冲 I/O 已 5.33ms+，原"128 样本 ~3-4ms"数学错一倍；与 EXECUTION 事实表统一。"5ms 目标"的缓冲档位 = 64 样本；M7a 验收统一为 5ms 目标 / 8ms 底线（v0.7 #65）。

延迟工具拆分（`tools/latency/`）：

1. **引擎处理延迟**（core 内部可测，脉冲/MLS 注入）——唯一写入 CI 断言的工具
2. **端到端延迟**（含声卡 + OS 缓冲，回环测量）——物理设备人工跑
3. **宿主插件延迟**（VST3 宿主报告延迟）——DAW 人工验证

桌面音频后端（v0.7 修订）：**Windows = WASAPI 独占为主**（免驱动安装、即插即用）+ ASIO 可选（低延迟爱好者手动切换）；**WASAPI 提供独占/共享模式切换**（默认独占，独占屏蔽系统音频伴奏需在设置页说明）；**设备断开 = 自动重连 + 失败回退共享模式 + 非打断提示**（v0.7 #88/#107，§15 音频 I/O 设备管理开放问题闭合）；macOS = CoreAudio 默认；均为 JUCE 原生支持，M5 实现。

## 11. 嵌入式

### 设备选型分析（2026-08-13 用户质询后修订）

市场综合效果器的硬件形态有两类：

1. **传统大厂（Boss/Roland、Line 6、Fractal、Zoom）：DSP 芯片 + MCU 双芯片**。算法写在专用 DSP（ADI SHARC、TI C55 类）的专用 C/汇编里，MCU 只管 UI/整机控制。**此形态对本项目不成立**：NAM 是神经网络推理，传统 DSP 无 NN 指令集，A1/A2 跑不了；专用工具链意味着引擎整体重写，"双端共享引擎"作废；SHARC 单价数十美元 + 工具链许可费，省钱目的也达不到。
2. **现代新锐（Neural DSP Quad Cortex、IK Tonex）：通用 ARM 处理器**。QC 用 Xilinx Zynq（Cortex-A53），Tonex 用 STM32H7（Cortex-M7）——NAM A2 的 Lite 档（slimmable 3ch）正是为这类嵌入式 ARM 设计的。**本项目采用此路线**。

### 双档位硬件路线

| 档位 | 芯片/形态 | 引擎复用 | NAM 支持 | 量产 BOM | 定位 |
|---|---|---|---|---|---|
| **主力档** | 低成本国产 Cortex-A SoC（RK3308/RK3328 级）+ Linux + I2S codec | ~99%（原样编译 + NEON） | A1/A2 全系（档位按实测） | ~300 元（整机目标，含外置 DAC/耳放/屏/外壳，M4 bake-off 实测复算，v0.7 #69） | 完整功能量产形态 |

- **M0 起步：RK3308 ev 板**（~¥100-150，用户 2026-08-13 改判 #109：Firefly ROC-RK3308-CC / 芯板类）：验证引擎 Linux 原样编译（aarch64）、DSP+IR 实时性、内置 codec（8ch ADC/2ch DAC）音频路径、真实延迟数据；UAC2 spike 直接在本板跑（Linux UAC2 gadget）

### 平台分层

- **Linux 层（主力档）**：ALSA I2S + 声卡 codec，完整引擎；**UI = Web UI**（浏览器访问设备 IP，桌面 UI 响应式布局，独立前端工程 + 共享 design token，不用 JUCE WebView）；**Web UI 是控制源之一**（全功能编辑走引擎仲裁，含 undo，壳侧实现），演出模式锁破坏性操作（存储/覆盖场景需确认）；**CONNECTING/RECONNECTING/STALE 三态** + 重连后只读横幅（v0.7 #79）；**v1 信任模型声明：局域网信任模型**（无鉴权或基本认证，二选一 M7c 定；OTA 用 RSA/ECDSA 非对称签名，SHA-256 仅作摘要，v0.7 #68）；**M7a 验收标准量化**：5ms 目标/8ms 底线（64 样本 5ms 档实测）+ 24h 无爆音 soak test + BOM 成本验证
- **裸机/RTOS 层（低端档）**：I2S DMA + codec 驱动、FreeRTOS；**UI = 图形点阵 LCD 两级**（预设列表 + 参数，**中文字库，中文全端显示**——用户裁决，BOM +¥10-20/开发 +1-2 周，v0.7 #82）；默认承诺 DSP+IR；NAM（A1 / A2-Lite 档）能否实时跑为研究课题，能跑则激活
- **日常操作（两档共用）**：2-3 个脚踩开关（长按模式切换：预设模式/场景模式）+ 旋转编码器（push + 长按，浏览/参数分组"常用/全部"+ 旋转加速 + 长按返回）+ 小屏显示；LCD 导航状态机：顶层预设 → push 进参数 → 长按返回；**H7 低端档场景经 LCD 导航、调音器/设置 v1 不可达**（列入 M8 研究，随图形屏+中文验证，v0.7 #70）
- 双端共用 `core/`，HAL 不同实现
- **codec/ADC 选型（v0.6 事实修正）**：RK3308 内置 codec 为 **8ch ADC + 2ch DAC**（8ch I2S 采集侧、回放侧仅 2ch）——吉他输入（ADC 方向）可复用内置；**立体声主输出 + 耳机 + FX loop 回放需外置 I2S DAC**（AK4458/Cirrus 类，110dB+）或双 codec 方案；AK4458 是纯 DAC 无 ADC，输入路径需独立 ADC（AK5558/CS5340 类）或复用 RK 内置 ADC；避免 SoC 内置 codec 音质瓶颈（模拟前端另行设计）
- **H7 适配约束**：core 禁止依赖 STL 堆容器在音频路径（已有实时安全原则），适配点集中在分配器与线程抽象；H7 无 Linux，HAL 层提供裸机实现
- M0 增加一次 moddsp/modep（MOD Devices，开源嵌入式+桌面共享 LV2 踏板链）生态调研（半天），确认没有可直接省 3 个里程碑的路径
- **UAC2 spike 前置 M0-M1**（v0.5 裁决；v0.7 #106 修订验收口径；#109 起在 RK3308 上跑）：RK3308 Linux UAC2 gadget 枚举为声卡，验证录放（异步反馈 + I2S 本地晶振双时钟域是最深坑）；**M1 验收 = spike 跑通 + ≥8h 初步数据，24h 无漂移结论移 M2**，不等到 M7 才第一次碰

### 硬件接口清单（M7 拆分交付，v0.5 修订）

**模拟 I/O（M7a 核心 + M7b 扩展）**：
- 高阻抗吉他输入（1MΩ 缓冲电路，被动拾音器直插）+ 输入选择（吉他/线路）+ ESD 钳位/RFI 滤波（高阻输入是天线）
- **ADC 输入路径**（M7a，音质关键）：复用 RK3308 内置 8ch ADC（吉他 + 表情 + 辅助输入）或外置 ADC（AK5558/CS5340 类）+ 输入缓冲/增益级；M4 bake-off 时实测内置 ADC 底噪/动态范围，不足则换外置
- 立体声主输出（**外置 I2S DAC**：RK 内置 DAC 仅 2ch 回放且音质有限，主输出用 AK4458/Cirrus 类 + 平衡驱动；**统一地平面 + 单点星型汇接**，不搞"地分割"——割地=缝隙天线+地弹，v0.5 修正；XLR pin1 → 10Ω//0.1µF 抬升 + 星点，演出 PA hum loop 处理）
- 耳机输出（独立耳机放大器，插拔检测 + mute，16Ω 低阻驱动余量）
- 效果环路 Send/Return（M7b：4CM 接真实音箱；链上 Send/Return 路由节点引擎已预留；回放侧走外置 DAC 空闲通道）
- 表情踏板输入（M7b：TRS，10k-100k 电位器兼容偏置网络；音量/哇音/whammy 控制源；ADC 通道复用内置）

**数字接口**：
- USB（UAC2 声卡 + USB-MIDI + 固件升级三合一，M7c）：录干/湿信号、播放伴奏回放、DAW 直录；RK3308 用 Linux UAC2 gadget（configfs 组合设备），H7 用 USB 设备栈；**UAC2 异步反馈端点处理时钟漂移**；宿主 44.1k → 引擎保持 48k + USB 路径独立 SRC（时钟主从决策先于实现）
- WiFi（Web UI 配置 + 固件 OTA，M7c）
- **DIN MIDI 已砍**（v0.5 裁决：USB-MIDI 覆盖 90% 场景）

**电源与可靠性**：
- 9V DC 输入（容差 ~12V 无载，需降压稳压 + 反接保护）、**统一地平面 + 模拟供电滤波 + 单点汇接**（修正"分割"策略）、上电防爆音时序（mute → PLL lock → I2S 有效 → 引擎启动）、**掉电检测（supervisor）+ 储能窗口内完成 mute 序列**（9V 跌落瞬间 codec/耳放关机 pop 是第一投诉项，v0.5 补）
- 固件升级 v1（M7c）：**rkdeveloptool 恢复模式烧写 + 单槽 bootcount 自动回滚**（1-1.5 周）；真 A/B 双镜像后置 v2；升级对象 = 应用分区优先（小/快/可回滚）；**升级 7 态状态机**（检查更新→下载→校验→烧写→重启→结果/回滚提示；Web UI 作为升级工具需"等待设备重启"态，v0.7 #86）；OTA 签名 = RSA/ECDSA ≥SHA-256 摘要 + 断电中途失败兜底 + 升级期间 UI 明确"不可演出"状态
- 恢复出厂设置（bootloader 级长按进入 + LED 闪码/蜂鸣反馈；清数据分区 + 回 A 槽指示）

## 14. 主要风险

1. **嵌入式音频栈被低估**：ALSA/codec/I2S 驱动、爆音、优先级问题吃数周——M0 就买 STM32H7 核心板实测，用数据决定预算
2. **H7 上跑 NAM**：A2 降档（Lite 3ch）在 Cortex-M7 的实时性未实测（A2-Full:Lite 算力比 ≈7-15×，Lite 档"大概率可行但未验证"）；H7 默认 DSP+IR，NAM 实时性为研究课题，不是承诺；跑不动则主力档归 Cortex-A，H7 保持低端档
3. **WDF 建模工作量**：电路仿真质量取决于建模精度，已后置为迭代项；TS9/Klon 为注册商标，商业产品需改名
4. **VST3/AU 打包**：macOS 公证 + 开发者账号 + 证书是金钱和时间成本，提前办理开发者账号
5. **国产 SoC 供货/生态**：RK3308/RK3328 文档与 BSP 生态弱于树莓派，量产阶段需留 BSP 适配缓冲
